# 씬 돌 (Scene Doll)

웹툰 콘티 단계에서 3D 돌로 컷을 짜고, 배치한 돌의 구도와 앵글을 AI가 이해할 수 있는 결과물(이미지 + 텍스트)로 뽑는 브라우저 단독 프로그램입니다. 설치·서버 없이 주소로 열고, 데이터는 사용자가 지정한 작업 폴더에 JSON·PNG로 직접 저장합니다.

기획서: [scene-doll-spec.md](scene-doll-spec.md)

## 실행

- 배포 페이지: https://dldyd147-creator.github.io/scene-doll/
- 로컬 개발: `npm install` 후 `npm run dev` → http://localhost:5173
- 빌드: `npm run build` → `dist/` (정적 파일, 어디에 올려도 동작)
- 배포: `npm run deploy` (빌드 후 `gh-pages` 브랜치에 올림, 1~2분 뒤 반영)
- 테스트: `npm test`, 타입 검사: `npm run typecheck`

푸시할 때마다 자동 배포하려면 `deploy/github-pages.yml`을 `.github/workflows/deploy.yml`로 옮기면 된다. gh CLI 토큰에 `workflow` 권한이 필요하므로 먼저 `gh auth refresh -h github.com -s workflow`를 한 번 실행한다.

대상 환경은 윈도우 데스크탑의 크롬·엣지입니다. 작업 폴더 저장은 폴더 접근 기능(File System Access API)이 있는 브라우저에서만 되고, 그 밖에서는 브라우저 내부 저장(IndexedDB)으로 동작합니다.

## 화면

왼쪽부터 컷 목록 · 원고뷰(+카메라 패널) · 조작뷰 · 에셋 패널. 모든 편집은 조작뷰에서 하고, 원고뷰는 보기·카메라 조작·컷 확정만 합니다.

## 작업 흐름

0. **작품 관리**(시작 화면): 작품을 만들고(코드 3자 + 이름) 회차를 열면 편집 화면으로 간다. 캐릭터 관리에서 작품의 캐릭터를 등록한다: 이름·고정색·성별(돌)·키·나이·역할(주인공·조연·엑스트라 드롭다운, 모든 캐릭터 목록이 이 순서로 정렬)·한 줄 설명·설명·외형 태그(쉼표 구분), 레퍼런스 기본 8장(얼굴 정면·측면·반측면·반측면 2·후면, 전신 전면·측면·후면) + 추가 자료(복장·무기 등 이름 붙여 최대 10장), 대표 1장. 편집 화면 상단의 [작품 관리]로 돌아온다.
1. 에셋 패널 **캐릭터** 탭에서 + 를 눌러 그 캐릭터의 돌(성별 돌·키·고정색)을 꺼내고 조작뷰에서 자세를 잡는다. 작품과 무관한 돌은 **돌** 탭에서 필터를 '기본 돌'로 바꿔 꺼낸다(임시 캐릭터가 된다). 씬의 돌 카드에서 캐릭터를 바꿔 지정하거나 임시로 되돌린다.
2. 원고뷰에서 카메라를 잡는다: 드래그로 궤도 회전, Shift+드래그로 팬, 휠로 거리, Ctrl+휠로 화각. 카메라 패널에서 화면비·화각·위치(cm)·각도를 숫자로 끌어 조절한다. [시점] 줄의 아이레벨은 선택한 캐릭터의 눈높이에 수평으로, POV는 그 캐릭터의 눈에서 머리 방향으로 카메라를 놓는다. 조작뷰의 카메라 아이콘을 끌거나 G/R, W/E 기즈모로 옮길 수도 있다.
2-1. **씬 라이브러리·씬 검색기**: 잘 짠 씬은 원고뷰 아래 책갈피 버튼(씬 저장)으로 `공용/씬/`에 넣는다. 인원(화면 안 돌)·샷·앵글·화면비·배치는 프로그램이 자동 태그로 붙이고, 상황 태그(대화·독백·대치·전투·이동·리액션·일상·로맨스·군중·설정샷, 설정에서 편집)만 버튼으로 찍는다. 캐릭터 지정은 저장하지 않고 돌 슬롯(돌 ID·키·위치·회전·관절)·소품·카메라·화면비만 남겨 다른 작품에서도 쓴다. `` ` ``(백틱) 또는 돋보기 버튼으로 **씬 검색기**를 열면 썸네일 격자 위에 태그 버튼 줄(샷·앵글·인원·상황)과 이름 검색이 있다. 버튼을 누르면 걸러지고 다시 누르면 풀린다(같은 묶음은 '또는', 묶음끼리는 '그리고', 상황 태그는 누른 것을 모두 가진 씬만). 썸네일을 고르면 미리보기가 커지고 슬롯마다 이 작품의 캐릭터를 지정한다(비우면 임시 캐릭터). [교체]는 현재 컷의 씬 전체(카메라·화면비 포함)를 바꾸고, [추가]는 돌만 더한다. 어느 쪽이든 지정한 캐릭터의 돌(성별 돌·키·고정색)로 들어온다. 에셋 패널 씬 탭에 최근 저장 씬이 보인다.
2-2. **포즈 라이브러리**(에셋 패널 포즈 탭): 선택한 돌의 관절 회전값을 이름·분류·태그와 함께 `공용/포즈/`에 저장하고, 카드를 누르면 선택한 돌에 적용한다(돌 공간 회전이라 체형과 무관). 분류 칩으로 거르고 카드의 ×로 지운다. **끌어다 놓기**: 캐릭터 카드·기본 돌 이름을 조작뷰로 끌어다 놓으면 그 바닥 자리에 돌이 서고, 포즈 카드를 돌 위에 놓으면 그 돌에 적용된다.
2-3. **글콘티(NTT 엑셀) 연동**: 원고뷰 제목 줄의 문서 아이콘으로 `.xlsx`(또는 CSV)를 고르면 첫 행을 보고 열(컷 번호·화자·대사·지문·비고)을 자동으로 잡고, 매핑을 확인한 뒤 회차 컷 전체에 대사·지문을 한 번에 넣는다(비고는 메모에). 컷 번호가 빈 행은 앞 컷에 이어 붙고, 컷 수가 모자라면 마지막 컷을 복사해 만들며, 글콘티에 없는 컷은 그대로 둔다(순서는 바꾸지 않음). 이후 원고뷰 위에는 그 컷의 대사(한 줄에 하나, `화자: 대사`), 아래에는 지문과 확정 때 만든 장면 설명이 보이고 대사·지문은 바로 고친다. 회차에는 `scriptSource`(파일명·가져온 시각)가 남고, 출력 `.md`의 컷 블록에 `대사(화자):`·`지문:` 줄이 더해지며 AI 전달 패키지에도 그대로 들어간다. 엑셀 없이 대사·지문 칸만 켤 수도 있다.
2-4. **소품**(에셋 패널 소품 탭, 3단계): 프리셋(검·단검·막대·컵·책·휴대폰·공·상자)이나 기본 도형(상자·원기둥·구, cm 단위)·색·태그로 등록하거나 GLB 파일을 넣는다(`공용/소품/{ID}.json` + `.glb` + 썸네일 `.png`, 공용 또는 이 작품 전용). [놓기]로 씬에 자유 배치하고 [오른손]/[왼손]으로 선택한 돌의 손에 쥐어 준다(카드를 돌 위에 끌어다 놓으면 오른손). 소품은 클릭해 끌거나 G/R·W/E로 옮기고 돌리며, 손에 쥔 채 옮기면 쥐는 위치·각도(손 뼈 로컬 오프셋)가 바뀌고 [쥐기 저장]으로 그 손의 기본값이 된다. 돌과 같은 2단 셀 명암·외곽선으로 그려져 출력·썸네일·패키지에 그대로 들어가고, 설명 텍스트의 인물 줄에 "오른손에 검", 자유 배치는 "소품: 컵" 줄이 붙는다. 카메라 버튼은 **단독 촬영**: 돌 없이 소품만 찍어 `출력/{작품코드}/{회차}/소품_{이름}.png`로 저장한다.
3. **컷 확정**(Ctrl+Enter): 원고뷰에 보이는 카메라를 컷에 맞춘 뒤 설명 텍스트가 자동 생성되고 썸네일이 컷 목록에 들어가며 다음 컷으로 넘어간다. 썸네일은 저장되는 컷과 항상 같은 화면이고, 확정된 컷을 고치면 잠시 뒤 다시 찍힌다. 상단의 출력물 보기 아이콘은 이 회차에 출력된 PNG가 있으면 색이 켜진다. 다음 컷이 없으면 방금 확정한 씬을 복사해 만든다. PageUp/PageDown으로 위아래 컷 이동, 컷 목록 아래 버튼으로 삽입·삭제·순서 변경.
3-1. **조작 고도화**(4단계): 팔·다리 뼈를 선택하면 툴바에 **팔꿈치°/무릎° 다이얼**이 나타나 손(발)은 그대로 두고 가운데 관절만 어깨→손 축 둘레로 돌린다. **몸통 따라가기**(툴바·설정)는 손 IK 핸들을 팔 길이 밖으로 끌면 상체가 그쪽으로 기운다(최대 45°, 관절 한계 안). **핸드 오퍼레이터**(툴바 손 아이콘)는 선택한 돌의 왼손·오른손 손가락 모양을 잡는 창이다: 손바닥 쪽에서 본 손 확대 보기(끌어서 돌려 봄), 전체·손가락별 굽힘 슬라이더, 기본 프리셋 6종(펴기·자연스럽게·쥐기·주먹·가리키기·엄지 척), 저장한 손 모양(이름 붙여 `공용/손포즈/`에 저장, 어느 돌에나 적용·삭제), 반대 손에도 같은 모양. 조작뷰에서는 손목까지만 돌아가고 손가락은 여기서만 다룬다. 소품을 쥐어 주면 '쥐기'가 자동으로 들어간다.
4. **출력**: 컷 목록의 출력 버튼으로 확정 컷 전체를 `출력/{작품코드}/{회차}/`에 PNG(가로 1024px, 설정 가능) + 컷별 JSON + 회차 설명 `.md`로 내보낸다. '선화·깊이·색 마스크 묶음'(기본 켬)이면 컷마다 `_line.png`(흰 돌 + 외곽선·십자선), `_depth.png`(가까울수록 밝음, 배경 검정), `_mask.png`(캐릭터 고정색·소품색 평면, 배경 투명)가 출력 폴더와 패키지 컷 폴더에 함께 생기고 패키지 JSON의 `images`에 이름이 적힌다.
5. **AI 전달 패키지**: 출력 때 '함께 추출'(기본)이면 `패키지/{작품코드}/{회차}/`에 컷 폴더(`{컷}/` PNG + `{코드}_{회차}_{컷}.json` + `prompt.md`), 캐릭터 시트(`캐릭터/{이름}/{이름}.md` + 레퍼런스 복사), `회차.json`, 회차 설명 `.md`가 생긴다. 컷 JSON과 prompt.md에는 화면 안 캐릭터(돌 색 → 이름, 등록 여부, 설명, 외형 태그, 위치·향함·자세, 레퍼런스 경로)와 장면(자동 설명·메모·대사·지문·카메라)이 들어 있어 이미지 API에 그대로 붙인다. 등록되지 않은 돌은 "임의의 남성/여성"으로 그리라고 적힌다.
6. **이미지 생성**(5단계, 상단 바 반짝 아이콘): 확정 컷을 묶음 태그끼리 4컷(설정 6·8) 단위로 묶고(나머지가 한 컷만 남지 않게 균등 분할, 태그 없는 컷은 순서대로), 묶음마다 돌 렌더를 격자 한 장(1·2·3컷은 한 줄, 4컷 2×2, 5~6컷 3×2, 7~8컷 4×2, 칸 왼쪽 위에 번호)으로 합성한다. 화면비가 다른 컷은 가장 긴 화면비의 칸 안에 세로 가운데로 놓이고 여백은 회색이다. 등장 캐릭터의 대표 레퍼런스(설정으로 캐릭터당 1~3장, 전체 16장 상한)와 선택한 선화·색 마스크 격자를 함께 첨부한다. 프롬프트는 자동으로 쓰인다: 격자 설명 + 칸↔컷 대응표 + 색→캐릭터 대응표(등록 정보·레퍼런스 첨부 번호) + 첨부 목록 + 컷별 블록(확정 설명 텍스트 그대로) + 강도 프리셋 문구 + 화풍 문구 + 규칙. 강도 3단계는 **돌 우선**(정확히 따름, 원본 렌더, 충실도 높게) / **균형**(참고, 원본 렌더) / **프롬프트 우선**(느슨한 참고, 캐릭터 고정색 실루엣 입력, 충실도 낮게). [묶음 준비]는 네트워크 없이 이것들을 만들어 묶음마다 격자 미리보기와 프롬프트(수정 가능)를 보여 주고, [보내기]로 엔진에 보낸다(진행률·취소). 결과 격자는 칸대로 잘려 `생성/{작품코드}/{회차}/{컷}/cand_{n}.png`로 저장되고 컷 JSON의 `generatedImages`에 경로가 적힌다(첫 장이 대표). 자를 때 모델이 칸 경계에 그려 넣은 검은 선을 열·행 밝기 프로파일에서 찾아(기대 위치 ±5%) 그 두께만큼 비켜 자르고, 완료 화면에 모델·토큰 사용량·경계선 검출 결과를 보여 준다. **후보 비교** 탭에서 컷별 후보 썸네일을 보고 대표를 고르거나 지우고, 실패 컷(생성 거부·오류)만 단독 또는 재묶음으로 다시 생성하며, 컷 하나만 단독 생성할 수도 있다. 엔진은 설정에서 **모의**(네트워크 없이 돌 격자에 MOCK 표시, 흐름 확인용)와 **원격**(사용자가 배포한 서버리스 함수) 중 고른다. OpenAI API 키는 브라우저에 두지 않고 함수의 환경 변수에만 둔다. 함수 배포와 연결은 [serverless/README.md](serverless/README.md).

설명 텍스트는 고정 어휘로 쓴다: 샷 4종(클로즈업·바스트·웨이스트·풀샷), 앵글 3종(하이·아이레벨·로우), 위치 9칸(왼쪽·중앙·오른쪽 × 앞·중간·뒤. 앞뒤는 카메라 거리 차가 0.3m·가까운 쪽 거리의 12% 이상일 때만, 같은 칸에 둘 이상이면 '중앙 (파랑 돌 왼쪽)'처럼 서로의 좌우를 덧붙임), 향함 8방위, 자세 문구(관절 각도 규칙). 사람이 고칠 것은 메모 줄뿐이다.

## 조작 (디자인돌 방식)

| 조작 | 동작 |
| --- | --- |
| 몸 부위 드래그 | 그 관절이 바로 회전 |

UI는 밝은 테마가 기본이고 설정에서 어둡게 바꿀 수 있다. 상단 오른쪽의 ? 가 도움말, 그림 아이콘이 출력물 보기(브라우저는 탐색기를 직접 열 수 없어 앱 안에서 본다)다.

## 코드 구조

```
src/
  model/      데이터 구조(작품·회차·컷·캐릭터·돌·포즈·씬·소품)와 기본값, 씬·포즈 라이브러리 순수 로직(library: 컷→씬, 필터, 슬롯→돌), 소품 정의·프리셋(props)
  engine/     three.js 엔진: 뼈대·마네킹/GLB 돌·IK·상호작용·원고 카메라·십자선·외곽선·오프스크린 렌더, 소품 객체·손 뼈 쥐기(props, propMath)
  describe/   설명 텍스트: 컷 분석(화면 안 판정·샷·앵글·배치·향함·자세)과 .md 형식
  script/     글콘티(NTT 엑셀) 연동: 의존성 없는 .xlsx 리더(zip+XML), CSV, 열 매핑 자동 판정, 컷별 대사·지문 반영
  generate/   5단계 이미지 생성: 엔진 인터페이스(engine: 모의·원격), 묶음 순수 로직(batch: 묶기·격자·요청 크기·분할·프롬프트), 캔버스 합성·분할(compose), 준비·실행 흐름(runner)
  state/      zustand 스토어(문서·컷 목록·선택·되돌리기·설정)
  storage/    저장소 모듈(작업 폴더 / 브라우저 내부), 폴더 구조, 작품·회차·캐릭터·레퍼런스·썸네일·출력·패키지·생성 후보·공용 씬/포즈 쓰기
  ui/         React 화면: 시작 화면(StartScreen), 캐릭터 관리(CharacterManager), 편집 화면, 씬 저장·검색기(SceneSaveDialog·SceneBrowser), 포즈·씬 탭(PoseTab·SceneTab), 컷 확정·일괄 출력(exporter)·AI 전달 패키지(packager), 이미지 생성 대화상자(GenerateDialog)
serverless/
  openai-image/  OpenAI Images API 중계 함수 템플릿(Cloudflare Worker 권장, Vercel 예시). 키는 여기 환경 변수에만. 배포 절차는 serverless/README.md
```

## 돌과 포즈 데이터

- 뼈 이름은 Mixamo 표준(접두어 없음), 휴식 자세는 T포즈.
- 관절 회전값은 **돌 공간에서 휴식 자세 대비 회전 쿼터니언**으로 저장합니다. 뼈의 로컬 축 규약에 의존하지 않아, 같은 이름·T포즈 뼈대를 가진 어떤 돌(코드 마네킹, MakeHuman, 실제 GLB)에도 같은 포즈를 적용할 수 있습니다.
- 기본 돌은 MakeHuman(CC0) 2세대 남·여로, 팔다리에 트위스트 뼈 8개가 있어 비틀림이 어깨·손목에 걸쳐 풀립니다. 캡슐 마네킹은 테스트용입니다. 점검 보고는 [docs/doll-report.md](docs/doll-report.md), 생성 스크립트는 `doll-src/makehuman/`.

## 공유 저장소(협업)

여러 사람이 같은 작품을 쓰려면 Supabase 프로젝트를 하나 만들고([serverless/supabase/README.md](serverless/supabase/README.md)), 시작 화면의 **공유 저장소** 칸에 Project URL과 anon 공개 키를 넣은 뒤 이메일·비밀번호로 로그인한다. 로그인하면 `작품/`·`공용/`은 공유 저장소에서 읽고 쓰고, `출력/`·`패키지/`·`생성/`은 그대로 내 작업 폴더(또는 브라우저)에 남는다. 자체 서버는 없다.

- **회차 잠금**: 회차를 연 사람이 기록되고 다른 사람에게는 보기 전용이다(상단에 빨간 칩, 컷 편집·확정·저장 차단, 시작 화면 회차 타일에 배지). 5분 동안 신호가 없으면 넘겨받는다.
- **실시간**: 다른 사람이 씬·포즈·소품·손 모양을 저장하면 내 라이브러리가 바로 다시 읽힌다.
- **작업 로그**: 로그인·회차 열기·컷 확정·출력·씬 저장·작품/회차 만들기와 삭제·올리기/내려받기를 기록하고 시작 화면에서 작품별로 본다.
- **올리기/내려받기**: 내 폴더의 작품·공용을 공유로, 또는 공유를 내 폴더로 복사한다(이미 있는 파일은 건너뜀).

권한은 작품별 `read`/`write`/`admin`이고 작품을 처음 만든 사람이 admin이다. 저장 코드는 `src/storage/remote/`에 있고 화면·3D 코드는 저장 방식을 모른다.
